# Native Execution Summary & Prerequisites

## 1. What We've Built So Far
We have successfully decoupled the entire Debezium CDC pipeline from Docker and adapted it to run natively across your Windows host machine + WSL. Here is a summary of the implemented components:

* **Kafka Extensibility Script (`setup_ubuntu_debezium.sh`):** A bash script created to download the Debezium MongoDB `.jar` plugins natively into your WSL Kafka installation.
* **Debezium Configurations (`connectors/*.json`):** We mapped out the CDC configuration for both the `orders` and `products` collections. **Crucially**, we bypassed Avro and Schema Registry requirements, configuring it to leverage raw `JsonConverter` instead, which simplifies bare-metal setups tremendously.
* **Python Data Simulator (`src/generator/simulator.py`):** An intelligent Python script that programmatically initializes the MongoDB Replica Set (resolving all native routing issues), seeds initial records, and indefinitely streams fake `INSERT`, `UPDATE`, `REPLACE`, and `DELETE` mock traffic into MongoDB.
* **Connector Manager (`src/connector/manager.py`):** A custom Python REST API manager that continuously polls Kafka Connect's health, uploads your configuration JSONs seamlessly, and restarts any tasks if they randomly crash.

---

## 2. Prerequisites for Native Execution
Before running the startup steps, you must ensure the following are installed directly on your systems:

### On WSL
* **Java 11+** installed (`java -version`).
* **Apache Kafka** downloaded and running (recommended: **KRaft mode**, no ZooKeeper).

### On Windows
* **Python 3.9+** installed (`python --version`).
* **MongoDB Community Server** installed.
* **PostgreSQL 16** installed (for later phases).
* All Python packages installed via `pip install -r requirements.txt`.

## 3. Step-by-step Execution Flow
To bring the entire CDC pipeline to life securely, follow these ordered steps:

### Step 1: Start Kafka on WSL (KRaft mode; no ZooKeeper)
*Open your WSL terminal:*
1. Generate a cluster id:
   ```bash
   bin/kafka-storage.sh random-uuid
   ```
2. Format local storage (replace `<CLUSTER_ID>` with the value from step 1):
   ```bash
   bin/kafka-storage.sh format -t <CLUSTER_ID> -c config/kraft/server.properties
   ```
3. Start Kafka:
   ```bash
   bin/kafka-server-start.sh config/kraft/server.properties
   ```

### Step 2: Configure & Start Kafka Connect
*Still in your WSL terminal:*
1. Run `./setup_ubuntu_debezium.sh` to download the Debezium Mongo plugins.
2. Edit your Kafka configuration `config/connect-distributed.properties`. Look for `plugin.path` and set it to `/home/<your-user>/kafka-plugins` (as generated by the script).
3. Start Kafka Connect: `bin/connect-distributed.sh config/connect-distributed.properties`

> Note: Some older tutorials start ZooKeeper first. For this repo we standardize on **KRaft** to avoid ZooKeeper entirely.

### Step 3: Start MongoDB as a Replica Set
*Open your Windows Terminal/PowerShell:*
1. Rather than starting MongoDB via Windows Services, execute this command directly in your terminal to force Replica Set mode (which Debezium requires):
   ```powershell
   mongod --replSet rs0 --bind_ip localhost
   ```

### Step 4: Run the Python Simulator
*Open a new Windows Terminal:*
1. Run the Python generation application:
   ```powershell
   python src/generator/simulator.py
   ```
   *This script forces MongoDB to formally initiate the `rs0` replica set, builds the strict validation JSON schemas, and starts pumping fake eCommerce data continually.*

### Step 5: Register the Debezium Connectors
*Open a final Windows Terminal:*
1. Execute the registration pipeline manager:
   ```powershell
   python src/connector/manager.py
   ```
   *This tool watches for `localhost:8083` (Kafka Connect port), uploads `orders-connector.json` and `products-connector.json`, verifies they hit the `RUNNING` state, and silently watches for any connector failures.*

**Outcome:** At this point, Debezium is officially tailing your local MongoDB operations log and streaming every micro-change seamlessly into your local Kafka 9092 instance!
